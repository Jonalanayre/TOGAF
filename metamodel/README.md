# Metamodel

The metamodel is a shared vocabulary for documents, fields, and relationships. It is written in ordinary Markdown and is not enforced by code.

- [Record types](record-types/README.md)
- [Relationships](relationships/README.md)
- [Naming and identifiers](naming-and-identifiers/README.md)

Record a subject once in its home domain. Most work starts with an application, integration, capability, or data entity. Other types are optional when useful.

## Common information

| Field | Guidance |
| --- | --- |
| Name and purpose | What the subject is and why it matters |
| Owner | Accountable person or team; use TBD if unknown |
| Documentation status | Draft, Verified, or Deprecated |
| Architecture state | Current, Proposed, or Historical |
| Source / evidence | Original document, review, or other supporting reference |
| Last reviewed | YYYY-MM-DD or TBD |
| ID | Optional stable identifier |

A verified proposal is still proposed. Approval is separate from factual accuracy. No YAML metadata is required.
