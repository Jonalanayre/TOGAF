# Enterprise Architecture

A blank, documentation-only repository organized around the four TOGAF architecture domains: Business, Data, Application, and Technology. This is a tailored folder layout, not a mandatory TOGAF structure or a claim of complete framework compliance.

## Four architecture domains

| Domain | Contents |
| --- | --- |
| [Business architecture](business-architecture/README.md) | Organizations, objectives, capabilities, processes, value streams, and services |
| [Data architecture](data-architecture/README.md) | Shared data concepts, entities, definitions, ownership, and relationships |
| [Application architecture](application-architecture/README.md) | Applications, application services, and integrations |
| [Technology architecture](technology-architecture/README.md) | Technical components, networks, technology services, and environments |

## Supporting areas

- [Governance](governance/README.md): principles, standards, decisions, reviews, and exceptions.
- [Change](change/README.md): initiatives, requirements, target designs, roadmaps, and technical debt.
- [Reference](reference/README.md): blank templates and reusable guidance.
- [Metamodel](metamodel/README.md): plain-language record and relationship conventions.
- [.github](.github/README.md): pull request template only.

Start with [START-HERE.md](START-HERE.md). All files are Markdown. No scripts, Python, workflows, JSON schemas, YAML front matter, or populated company records are included.

Keep one home per subject. Link related subjects instead of scattering or duplicating their details.
